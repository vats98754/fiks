## Design notes for RBA

- Nothing from the clone runs on the host. The host's auto-mode classifier also refused a host
  `pnpm install` of the clone, which confirms the choice. Every build, server run and suite run
  is in the SBX image with `--network none`.
- No base-URL env: the server hard-codes `https://api.figma.com/v1` and fetches the S3 URLs the
  API returns. The upstream is replayed by a loopback HTTPS CONNECT proxy inside the container
  (`HTTPS_PROXY`, honoured by the server's undici `EnvHttpProxyAgent`), so `baseUrlEnv` is empty.
  A FIGMA_API_KEY env var would be refused by the SBX backend (`*API_KEY*`), so the dummy key is
  a CLI flag. Telemetry is off (`--no-telemetry`, `DO_NOT_TRACK=1`).
- The clock is not frozen: the tool has no time-dependent behaviour, and the RBX +10-year skew
  would invalidate the TLS certificate.
- SBX `ciLocal` cannot mirror this repo's CI on a *linked* git worktree: its first step
  (`scripts/scan-hidden-chars.mjs`, `git ls-files`) fails in the container because the worktree's
  `.git` file points at a host path. The remaining CI steps were run directly (below).
- `suiteScope` (10 files) is the set that passes deterministically in the sandbox. Excluded:
  `stdio.test.ts` and `server.test.ts` (each spawns `tsx src/bin.ts`; a cold tsx start of the
  server takes about 80 s in the sandbox, against 15 s / 30 s test timeouts, so they fail on both
  heads, in parallel and serial runs), and `integration.test.ts` (needs a real token and network).
