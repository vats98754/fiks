## 2. Top 5 weaknesses
1. **ALERT is a strawman, and its "four wrong fixes" are mostly artifacts of the harness.**
   - ALERT had no stored v2 trace and no re-recording step.
   - The correct D3 fix adds a header, which forces a re-recording of the v1 fixture (`D3-nohint-r1` re-recorded `order-create`). ALERT's gates therefore could not pass the right fix.
   - The agent said so itself (D3-alert-r0): "This change does not fix the alert itself", and it reported that adding the header "would break replay of the v1 fixtures".
   - The paper's own L1 and COMP (§7) replay the trigger; ALERT does not.

   *Fix [writing, 1 h]:* disclose this and relabel the D3 ALERT runs as declined and blocked by the harness. *Fix [experiment, ~$3, 2 h]:* add an ALERT+ arm with trace replay and re-recording, 15 runs.
2. **The "held-out live check" is not independent of the gates.**
   - It applies the same contracts to the same triggering call, plus 10 v1 calls on the bench entities.
   - `get_product` has no `price.equalsUpstream`, so the paper's own known fake fixes (a constant in-range D2 price, a D1 clamp) would pass it.
   - FIKS's 25/25 therefore amounts to being gated on oracle X and then evaluated on oracle X run live.

   *Fix [experiment, ~3 h, $0]:* compare tool output with the vendor database on unseen entities, re-score all 55 heads, and add the two fake fixes.
3. **Every comparison is null, but the abstract and conclusion read as positive.** E-A gives p = 0.50 and 1.00, and the bench gives p = 0.50. The whole FIKS–ALERT gap is D3 (confounded by item 1) plus one D4 run. *Fix [writing]:* put the p-values and the single-drift dependence in the abstract.
4. **No real subjects; one author wrote the drifts, contracts, mutation operators and tasks.** E-B confirms the circularity: 8.4% recall outside the coupled kinds, and `readAfterWrite` was never exercised (all 16 M14 mutants raised tool errors). *Fix [experiment, days]:* reproduce one or two real silent bugs in public MCP servers. *Fix [writing]:* reposition the paper as a tool/demo paper.
5. **The false-alarm evidence is still small.** The "every product, every category" sweep is 32 calls over 16 entities (per-call upper bound 10.7%), barely more than the bench's 37 calls. *Fix [experiment, ~1 h, $0]:* generate argument families to reach 500 or more clean calls.

## 3. Does E-A answer "no baseline"?
**Partly.**
- **NOHINT is a fair control.** Removing the hints changed 1 of 15 outcomes, which defuses the hint-leak objection.
- **ALERT is not monitor plus coding agent.** It changes five things at once: no visible test, no repro gate, no triggering trace in the stored traces, no re-recording, and no contract JSON. It therefore cannot isolate the fail-first property.

The supported reframing: *"On five seeded drifts, a repair agent's green gates tracked the contract-level outcome only when the gates replayed the triggering call; without that replay, gates passed patches that left the violation in place. Prompt hints mattered little."* That supports "replaying the trigger is a necessary gate". It does not support "the fail-first test keeps wrong fixes out".

## 4. Unsupported, inconsistent or overclaiming statements
- **Conclusion:** "the ablation suggests that the fail-first test is what keeps wrong fixes out of a pull request when the agent misdiagnoses the fault". Five factors are confounded, and the D3 agent did not misdiagnose silently: it declined.
- **Abstract:** "fixes passed a held-out live check in 25/25 runs … but 11/15 given only an alert and trace, whose gates accepted four wrong fixes". It omits p = 0.5 and overstates how held-out the check is, and three of the four wrong fixes are artifacts (item 1).
- **§5.6:** "removing the fail-first test let wrong fixes through the remaining gates". Same attribution problem.
- **Abstract:** "In planned exploratory follow-ups". These were run, not planned. The abstract also still says "We release a draft pre-registration", although the subtitle has dropped that framing.
- **§4.3 against Appendix A.** §4.3 says the prompt is "as first committed in 8c7daa8". Appendix A says the D1–D3 and D5 repairs ran "from an uncommitted tree that predates commit 8c7daa8". The verbatim prompt is therefore unverified for four of the five pilot repairs.
