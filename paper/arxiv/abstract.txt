LLM agents act on tool results as ground truth, but tools can fail silently: a Model Context Protocol (MCP) server returns a well-formed success whose content is wrong, for example after its upstream API changes behaviour without changing its schema. Studies of MCP faults, agent robustness and benchmark tooling show that such failures occur, that agents rarely notice them, and that schema checks and specification diffs do not see them; runtime monitors can warn the current agent, but the tool stays broken for every later one. We present fiks, a loop that turns a silent tool failure into a reviewable fix. A proxy checks every successful MCP result against an outcome contract, including agreement with the raw upstream HTTP exchange and read-after-write, and returns a receipt to the agent. A violation is compiled into a deterministic reproduction test that must fail on the current code for the named property; a tool-restricted coding agent repairs the server; and a pull request is opened only after that test, the full contract suite, all stored traces, typecheck, lint and CI on the exact commit pass. fiks never merges. In a pilot with 5 seeded drifts on a mock vendor whose OpenAPI document does not change, fiks flagged all 5, produced a valid fail-first test for each, and obtained a green-CI pull request in one repair attempt per drift (1.4--1.6 minutes from violation to pull request; $0.11--$0.21 per repair at API prices). In a 6-task, 5-trial agent bench, pass^5 was 50.0% without fiks, 83.3% with receipts and 100.0% after the fixes were merged; the pilot is too small to establish the receipt effect (sign test p=0.50), and an earlier receipt wording did worse than no monitor. We position fiks against a catalog of 508 sources, state which of its parts are not new, and release a pre-registration draft for a confirmatory study that has not yet been run.
