LLM agents' tools can fail silently: a Model Context Protocol (MCP) server returns a well-formed success whose content is wrong, for example after its upstream API changes behaviour but not its schema. Such failures occur and agents often adopt the wrong values; a schema checks shape, not meaning. Runtime monitors warn the current agent, but the tool stays broken for later ones. We present fiks, which turns a silent tool failure into a reviewable fix. A proxy checks each successful MCP result against an outcome contract (including agreement with the raw upstream exchange and read-after-write) and returns a receipt to the agent. A violation becomes a deterministic reproduction test that must fail on the current code for the named property; a tool-restricted coding agent repairs the server; and a pull request is opened only after that test, the contract suite, stored traces, typecheck, lint and CI on the exact commit pass. fiks never merges. In a pilot with 5 seeded drifts on a mock vendor whose OpenAPI document is unchanged, fiks flagged all 5, built a valid fail-first test for each and got a green-CI pull request in one repair attempt per drift (1.4--1.6 min from violation to PR; $0.11--$0.21 per repair at API prices). In a 6-task, 5-trial agent bench, pass^5 was 50.0% without fiks, 83.3% with receipts and 100.0% after the fixes were merged; the pilot is too small to establish the receipt effect (sign test p=0.50), and an earlier receipt wording did worse than no monitor (also not significant). In planned exploratory follow-ups, contracts caught 8.4% of silent response mutants outside the fault kinds they were written for, and in a sandboxed ablation (55 repairs) fixes passed a held-out live check in 25/25 runs with fiks's inputs but 11/15 given only an alert and trace, whose gates accepted four wrong fixes. We release a draft pre-registration for a confirmatory study not yet run.
