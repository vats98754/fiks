## Fix
Since vendor API version 2026-10-01, `/products` returns results in pages, which the published spec already allowed through `cursor` and `next_cursor`. The cable search came back with 5 of 7 items, `"total":7` and `"next_cursor":"5"`. The `search_products` handler only read the first page, so it quietly dropped the rest. The fix, in `src/tools/search_products.ts`, keeps requesting `&cursor=<next_cursor>` until no cursor comes back, and adds each page's items to the list. The cents-to-dollars conversion now runs on every page, based on that page's `vendor-api-version`. The old vendor version sends `next_cursor: null`, so it still makes a single request and the v1 fixtures give the same output as before. Typecheck, lint and the 7 other test files pass. The repro test now fails only with the expected UNMATCHED_REQUEST for the new `GET /products?q=cable&cursor=5`, which fiks will fix when it re-records the call.
