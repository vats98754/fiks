## Fix
Starting with vendor API version 2026-10-01, the vendor sends `price` in cents (p-1001 = 119900) instead of dollars, but the published spec wasn't updated. `search_products` was passing that number straight through, so agents got prices 100× too high. The fix in `src/tools/search_products.ts` reads the `vendor-api-version` response header and divides `price` by 100 when the version is 2026-10-01 or later; older versions are left as they are. The request is unchanged, the repro test now passes, and the v1 fixtures give exactly the same output as before (the full typecheck, lint and test runs all pass). `get_product` also returns the raw vendor `price` and probably has the same problem, but I didn't change it because it wasn't part of this failure.
