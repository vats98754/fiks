## Fix
Vendor version 2026-10-01 now sends `created_at` as a number of milliseconds since 1970 (e.g. `1792142857943`), even though the spec still says it's an ISO-8601 string. `get_order` ran the value through `Date.parse(String(...))`. A string of digits doesn't parse as a date, so the code fell back to `|| 0` and returned 1970-01-01. The handler now uses a numeric `created_at` directly as milliseconds and keeps parsing strings as before, so the 2026-01-01 v1 fixtures give exactly the same output. The change is in `src/tools/get_order.ts`. `pnpm typecheck`, `pnpm lint` and `pnpm test` all pass, including the repro test.
